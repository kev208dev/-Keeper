# Keeper 로컬 통합 시연 설계

## 의도

MacBook 한 대가 FastAPI, SQLite, 영상 파일 처리, 점주 웹 앱과 시연 제어를 제공하고, 같은 Wi-Fi의 Android 태블릿이 독립 네이티브 키오스크로 문의와 오프라인 Supertonic 3 음성을 담당한다. 실제 CCTV 없이도 생성 테스트 영상으로 세 흐름(감지, 문의, 연결 장애)을 반복 시연할 수 있어야 한다.

## 유지할 것

- FastAPI/SQLite/React 구조와 기존 이벤트 계약, 디자인 시스템, 인증 방식을 유지한다.
- 기존 `tts/android`의 Supertonic 3 Java 엔진과 모델 자산·라이선스 고지를 소스/자산 경로로 재사용한다.
- 기존 이벤트 ID 멱등성, 매장 격리, 점주 세션 인증을 유지한다.
- 결제 데이터가 없으면 `unpaid=false`로 기록하고 UI에 절도나 미결제를 확정 표시하지 않는다.

## 서버와 데이터 계약

- 기기는 안정적인 `deviceId`를 보내며 문의에 원 요청 기기를 저장한다. 답변 pull/ACK는 그 기기만 가능하게 하여 웹 시뮬레이터가 태블릿 답변을 소비하지 못하게 한다. 예전 클라이언트는 `legacy` 소비자로 계속 동작한다.
- `media` 테이블은 매장, 카메라, 종류(`recording`/`clip`), 상대 경로, MIME, 크기와 시간을 저장한다. 실제 파일은 `KEEPER_MEDIA_ROOT` 아래 매장별 폴더에 두고 정적 파일로 공개하지 않는다.
- 점주 인증 API는 녹화 파일 업로드/목록/인증 다운로드를 제공한다. 기기 인증 API는 분석기가 클립을 업로드하고 `clip.ready` 이벤트가 `mediaId`로 알림과 연결되게 한다.
- 카메라 및 클립 응답에는 `mediaId`를 포함하고 React는 Bearer 인증 fetch로 Blob URL을 만든 뒤 `<video controls>`에 연결한다.
- 감지 이벤트에는 `source`(`manual`/`analysis`), `confidence`, `reason`을 선택적으로 기록하여 시뮬레이션과 영상 분석을 구분한다.

## 영상 분석

- OpenCV의 CPU HOG 사람 검출기(Apache-2.0)와 중심점 추적을 사용한다. 별도 가중치 다운로드가 없고 Apple Silicon/Intel에서 실행 가능하다.
- JSON ROI는 다각형 이름과 좌표를 저장한다. 추적 대상 중심점이 ROI 사이를 옮길 때만 `확인 필요` 이동 이벤트를 만든다.
- 이벤트 전후 구간은 ffmpeg로 MP4 클립을 만들고 서버에 업로드한 뒤 `clip.ready`로 연결한다. ffmpeg가 없으면 명시적 오류로 종료한다.
- 사람 외 상품 훼손, 냉장고 문 상태는 모델이 지원한다고 주장하지 않는다. 시연기 수동 이벤트와 향후 별도 상태 입력 경로만 유지한다.

## Android 키오스크

- Java/Android API 26+, 가로 고정, immersive sticky 모드의 독립 앱이다. 홈, 문의, 음성 안내, 답변, 개발자 설정 화면을 네이티브 View로 구성한다.
- 서버 URL, 기기 키, UUID 기기 ID, 음성/속도/볼륨은 SharedPreferences에 저장한다. 문의 전송은 같은 eventId로 재시도하며, 5초 폴링과 앱 재시작 후 대기 문의 복구를 제공한다.
- 답변은 화면 반영 후에만 ACK하고 Supertonic 3 wrapper에 읽기를 요청한다. 단일 실행 큐와 generation token으로 중복/충돌을 막고 오류는 UI 상태로 돌려준다.
- 개발 빌드만 cleartext 로컬 HTTP를 허용하며 키는 코드에 포함하지 않는다.

## 시연과 운영

- 웹 시뮬레이터는 단계별 다음/일시정지/재시작, 간격, 로그, 서버·태블릿 상태, 영상 업로드를 제공한다.
- macOS 스크립트는 전용 `.demo/keeper-demo.db`와 `.demo/media`를 사용한다. setup/start/reset/check가 실제 의존성, 프로세스, API와 샘플 영상을 검사한다.
- 테스트는 매장 격리, 기기별 답변, 미디어 인증/경로 안전성, 중복 이벤트, 실제 생성 영상 분석/클립, React 영상 렌더링 및 Android 순수 Java 상태 로직을 포함한다.

## 명시적 제한

- Android 실기기의 ONNX 추론 속도·발음·발열과 실제 CCTV 정확도는 기기/영상 없이는 검증 완료로 표시하지 않는다.
- HOG 감지는 사람 이동의 단서만 제공하며 절도, 미결제, 상품 훼손을 판정하지 않는다.
- 스마트폰 실시간 스트림은 이번 로컬 촬영의 우선 완료 조건이 아니므로 파일 기반 구조 뒤의 확장점만 둔다.
